# 角色

本项目共五个角色：`超级管理员`、`管理员`、`仓管`、`销售`、`员工`。下表为初始化默认授权；受保护权限默认仅超级管理员持有，超管可在「用户与权限」→「受保护权限」解锁后授予其他角色（重新加锁自动收回已授角色），普通角色的实际授权以「用户与权限」→「权限矩阵」的实时数据为准。

| 模块                         | 超级管理员                                               | 管理员           | 仓管                                 | 销售             | 员工   |
| ---------------------------- | -------------------------------------------------------- | ---------------- | ------------------------------------ | ---------------- | ------ |
| 工作台、归档订单、库存       | 可见                                                     | 可见             | 可见                                 | 可见             | 可见   |
| 分析页（关系图、交付甘特图） | 可见                                                     | 不可见           | 不可见                               | 不可见           | 不可见 |
| 销售订单                     | 查看、新建、编辑、归档、归档回退、删除                   | 查看、新建、编辑 | 只读                                 | 查看、新建、编辑 | 只读   |
| 客户档案                     | 查看、新建、编辑、删除、批量移交                         | 查看、新建、编辑 | 不可见                               | 查看、新建、编辑 | 不可见 |

工作台（`menu:workbench`）是可授权菜单，默认对各角色可见，超管可在「角色与权限」中收回：收回后该角色登录落地到其授权内第一个页面（菜单字典顺序），直接访问 `/workbench` 会被前端守卫与后端 `/workbench/overview`（校验 `menu:workbench`）双重拒绝。矩阵与编辑器仍列出「备份」「恢复」等受保护项用于举证（2026-10 起统一口径）：仍受保护（默认仅超管）的系统组行超管列统一显示「超管专属」、其余角色「—」，与侧边栏标签一致；超管在「受保护权限」解锁某码后，对应菜单/动作即变为正常可勾选行，矩阵按各角色实时授权派生。「受保护权限」页签仅超级管理员可见，逐码提供解锁/加锁开关（须填原因，加锁立即收回所有角色已获授权）与审计记录；系统日志为普通可授权菜单（见下条），编辑器与矩阵按各角色实时授权正常派生；仓管侧边栏的「变更记录」为固定说明项，不占权限码，不出现在编辑器与矩阵中。

## 权限

- **BOM 结构维护默认仅超级管理员（2026-10 起，可解锁下放）**：`menu:bom-structure`、`bom-structure:view`、`bom-structure:manage` 均为受保护权限，默认仅超级管理员，超管可在「受保护权限」解锁后授予其他角色。页面在业务导航「物料与 BOM」旁（路径 `/product-structure`），维护新建 BOM 的可选目录（隐藏/恢复、新增分区/分组/物料、排序、规则、新建简单品类）——结构变更只影响之后新建的 BOM，已保存档案与订单/台账走冻结快照。读取复用 `GET /bom-categories`（`bom:view`，全量含停用标记），`view` 动作码仅作菜单/编辑器/矩阵举证（同分析页先例，无独立读端点）；写接口统一校验 `bom-structure:manage`。
- **备份与恢复默认仅超级管理员（2026-10 起可解锁下放）**：`menu:system-backup` / `menu:system-restore` 及其 `:run` 动作均为受保护权限。超管可在「受保护权限」解锁后经角色编辑器授予其他角色；重新加锁自动收回全部已授角色（已登录角色的权限随 grant_version 递增立即失效）。受保护开关本身仅 super 角色可操作，不随 `permissions:manage` 下放（防借解锁自我提权）。备份目录、预检、任务查询及执行端点统一校验受保护的 `:run` 动作，单独持有菜单码不能访问接口。包含 users 分组的备份含用户密码哈希，操作与保管要求见 [数据库备份/恢复](../db-scheme.md)。
- **系统日志（2026-10-13 起为普通可授权菜单）**：`menu:system-logs` 与 `system-logs:view` 自受保护清单降级（迁移 `20261013100000`），与分析页同口径——默认仅超管可见（不播普通角色授权行），超管可在「角色与权限」直接勾选授予其他角色，无需先在「受保护权限」解锁；聚合端点 `GET /system-logs` 校验 `system-logs:view`，菜单可见性仍以该菜单码授权为准。
- **AI 工作台默认仅超级管理员（2026-10 起，可解锁下放）**：`menu:ai-workbench` 为受保护权限，管理端点（配置读写/连通测试/用量统计）与菜单同码——解锁下放并授权后页面与接口一致生效（同备份/恢复模式）。AI 对话（`/ai/chat`、`/ai/chat/stream`、`/ai/status`）登录即可用（按登录人记账 token 用量）；agent 查询端点沿用各域既有权限码（作废入库 `inbound:view`、作废出库 `outbound:view`、删除审计 `system-logs:view`）——AI 助手能看到的＝该用户本人页面可见的。
- **分析页（2026-10 起）**：交付甘特图自工作台二级视图迁出为独立菜单 `menu:analytics`（侧边栏「工作台」组）。普通可授权菜单，默认仅超管可见，超管可在「角色与权限」按角色勾选授予；交付数据取自 `/workbench/overview`（校验 `menu:workbench`），业务关系图与 agent 分析数据取自 `/workbench/relations`（同时校验 `menu:analytics` 与 `menu:workbench`），只提供必要的业务关联、人员姓名/角色，不开放用户管理或联系方式；授予分析页的角色须同时保留工作台菜单。
- **删除是受保护动作**：`删除销售订单`与`删除 BOM`为受保护权限，默认仅超级管理员持有（2026-10 起超管可解锁后授予其他角色）——上表管理员、销售在`物料与BOM`、`销售订单`的"全部权限"均不含删除。订单仅可在净发货为 0、关联出库单均已作废并删除后删除；删除即物理删除（单据与变更日志同事务清除），立即从业务列表移除。BOM 仅可删除未被任何销售订单引用（含已归档订单——归档单永不删除）且无出入库/调整流水的档案——已删除的入库单物理消失即不再算引用，删除后 BOM 可立即删除。两处删除前端均有二次警告确认，后端独立校验并在操作日志留删除前快照。
- **归档回退仅归档人本人（2026-10 起）**：`归档回退`为受保护权限（默认仅超级管理员持有，可解锁下放）；操作者必须拥有回退权限，且为当前这次归档的操作者，其他超级管理员也不能代为回退，用于归档手误的补救。回退入口在归档订单页的订单详情（无权限或非归档人不显示按钮），无时间窗限制；回退后订单恢复编辑/发货，归档与回退过程均记入系统日志。
- **出入库已作废单可删除（2026-09 起；2026-10 起物理删除）**：`删除入库记录`/`删除出库记录`为非受保护权限，默认授予仓管与超级管理员（BOOTSTRAP），超级管理员可按需授予其他角色。仅已作废单可删（作废时库存与订单已发量已修正）；删除即物理删除——单据与变更/状态/数量流水同事务清除、列表不再返回，无恢复入口（删错直接重建单）；操作在系统日志（op_log）留单据终态快照（含作废原因）。被库存调整单引用的入库单不可删除。删除入口在查看详情抽屉，前端有二次警告确认，后端独立校验。
- **库存台账只由仓管写入**（超级管理员兜底），管理员、销售只读，保证账实数据出于一门。
- **客户资料只对销售线可见**（超级管理员/管理员/销售）：仓管发货只需订单信息，员工不可见。
- **客户完整手机号按归属受限**：客户联系电话在页面只显示掩码；完整手机号仅超级管理员（任意客户）与销售（本人负责的客户）可通过复制动作获取，管理员虽可见客户档案但无此入口，仓管/员工不可见客户。后端在接口独立校验归属，非负责人返回 403。
- **出库单只有两态**（2026-09 起）：已登记/已作废，"已打印"不再是状态；系统不提供出库单打印，纸质单据需求走线下流程。
- **入库当天可修正**：仓管、超级管理员可修改或作废北京时间当天录入的入库记录，每次操作必须填写原因并保存修改前后快照；二者规则一致。**跨天作废（2026-09 起）**：受保护权限`跨天作废入库`（默认仅超级管理员）可作废任意天数的已登记入库，前端对跨天作废弹二次确认警示；库存非负校验对跨天作废同样生效（隔天出库已消耗该批库存时拒绝）。修正不放开跨天——跨日发现数量错误仍只有超级管理员可新增库存调整单，原入库记录不再修改。
- **出库不原地修改**：登记错误且订单未归档时，有作废权限者可作废错误出库并重新登记，库存与订单已发量随冲销恢复。已作废单可按上条规则删除清理。真实发货后的客户退货不得作废原出库来处理；当前系统无销售退货流程，退货、验收与库存入账方式须在线下确认，原出库事实保留。
