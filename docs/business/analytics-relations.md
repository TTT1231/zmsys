# 业务关系图与 agent 数据接口

分析页的「业务关系图」位于交付进度上方。日期、订单状态、关联数据与统计均由后端 `GET /api/workbench/relations` 提供。页面默认近 30 天、进行中订单和全部实体类型；图例隐藏类型在当前响应内完成，不重复请求，接口仍支持 `types` 过滤供其他调用方使用。

多型号默认显示连通的全局依赖图，客户、人员使用真实实体节点，单据按所属型号折叠（显示入库、订单、出库笔数）。折叠后的边汇总原始关系与笔数，悬停或选中突出依赖；内部单据关系在点击型号后的业务树内展开，不伪造客户或人员直接关联 BOM 的原始边。全局节点与线路均为确定布局，连线沿列间通道绕开型号节点；缩小时以简洁标记显示，放大后显示卡片。

单型号业务树使用 SVG 卡片与折线，按「入库 → BOM → 销售订单 → 对应出库」分列，客户在上方、参与人员在下方；业务关系为实线、人员关系为虚线，保留两端当前可见的全部真实边，包括建档、制单、归档、出入库经办与客户负责人。入库不伪造订单归属。选中节点时显示关系名称，详情沿真实关系切换；在业务树内选择人员或客户保留当前树，也可点击“查看全局关联”追溯跨型号依赖。

入库每页 6 笔、订单每页 3 笔，选中订单后展开对应出库（每页 4 笔，也可收起）；仅有一笔订单时默认展开。默认清晰分支模式的分页仅限制当前挂载的卡片，不截断接口数据与统计。可切换“查看全部依赖”：一次呈现当前型号所有启用类型的实体与真实连线，不受单据分页或订单展开限制；缩小时用简洁节点表示，放大后显示卡片，可随时返回清晰分支。完整模式缩放下限为 10%，查找画布外的节点会将其移入视口。查找节点最多挂载 40 个候选，选中单据自动进入所属型号并定位到对应订单、单据所在页。详情位于画布旁，窄屏移至下方，不遮挡单据。清晰分支缩放下限为 70%，全局图和全部依赖模式允许缩到 10%，窄屏通过拖动画布查看完整分支；保留滚轮、缩放按钮、Home 适应画布、方向键移动/平移和 Escape 关闭详情等操作。

拖动 BOM 时其当前可见入库、订单和出库一起移动，拖动订单时仅带动它的当前可见出库，拖动流水只移动该笔；连线实时跟随。拖动只影响本地展示，不写业务数据。重新布局恢复确定的业务树位置，无力模拟或持续动画；主题变化保留位置与视角，未手动调整视角时容器变化自动适配，手动拖动/缩放后保留视角。切换单据页或型号时按当前内容重新布局。日期预设与自定义日期共用一个入口，支持输入精确 BOM 编号缩小历史查询。状态或日期切换取消旧请求；响应保鲜 30 秒、闲置查询缓存 60 秒，避免历史筛选组合长期驻留。

## 请求

使用现有 Bearer JWT。同时要求 `menu:analytics`、`menu:workbench`，超级管理员直通；沿用现有角色授权，不新增权限或数据库迁移。接口只读，可由前端或 agent 调用；不包含账号密码、联系方式、登录记录或用户管理数据。

| 参数            | 含义                                                                                |
| --------------- | ----------------------------------------------------------------------------------- |
| `start` / `end` | `YYYY-MM-DD`，包含首尾，支持单边；均省略时不限日期                                  |
| `status`        | `open`（默认）、`completed`、`archived`、`all`                                      |
| `types`         | 逗号分隔 `bom,customer,order,inbound,outbound,person`；省略为全部，空串为不显示节点 |
| `orderNo`       | 精确订单号                                                                          |
| `bomCode`       | 精确 BOM 编号                                                                       |
| `customerCode`  | 精确客户编号                                                                        |

例如获取已完成订单的 BOM、客户和销售订单关系：

```http
GET /api/workbench/relations?start=2026-10-01&end=2026-10-08&status=completed&types=bom,customer,order
Authorization: Bearer <accessToken>
```

例如核查某订单的出库及人员、客户、BOM 关联：

```http
GET /api/workbench/relations?status=all&orderNo=<订单号>
Authorization: Bearer <accessToken>
```

例如核查某个 BOM 在指定期间的入库、出库及所引用订单：

```http
GET /api/workbench/relations?status=all&bomCode=<BOM编号>&start=2026-10-01&end=2026-10-08
Authorization: Bearer <accessToken>
```

## 返回与计算口径

沿用 `{ code: 0, data: {...}, message: "ok" }` JSON 信封。`data` 包括：

- `schemaVersion`、`asOf`（当前北京业务日）、`generatedAt`、实际生效的 `filters`。
- `nodes`：稳定 `id`（类型前缀 + 数据库 ID 字符串）、实体 `type`、名称、中文 `properties`、机器可计算的 `facts`；作废节点带 `voided: true`。
- `edges`：`source`、`target`、关系名称及 `kind`。前端直接渲染；类型过滤后只保留两端都存在的边。
- `counts`：日期/编号条件下各状态的订单数，类型筛选不改变它。
- `typeCounts`：状态筛选后、类型筛选前的各实体数量，用于图例。
- `summary`：所选订单数、当前逾期订单 ID、按单位分组的订单量、累计有效出库和待交量；统计不随类型隐藏而变化。

日期按业务事件筛选：订单使用下单日，出入库使用业务日。期间内出库引用的旧订单保留，便于追溯；关联 BOM、客户与人员作为必要上下文保留。`status=all` 还包括期间内只有入库、尚无订单的 BOM；精确查询订单/客户时不夹带这些无关 BOM。

`completed` 按 **累计有效出库量 >= 订单数量** 判断，可能与 `archived` 重叠。`open` 是未归档且尚未交满。归档不代表交满：`unshippedQty` 保留历史未发量，`pendingQty` 为 0，不参与待交和逾期汇总。BOM 和客户没有“已完成”状态；该筛选表示它们与已完成销售订单之间的真实关系。

每次聚合在同一个只读事务内顺序读取（READ COMMITTED，各语句独立快照）取得单据、有效出库净额和当前库存，尽量缩小对账时混入并发写入的窗口（毫秒级，语句间仍可能相差一笔）。`order.facts.shipped` 来自 `v_order_outbound_qty`，`bom.facts.stock` 来自 `v_bom_stock`，均为**当前全生命周期净额**，不因日期筛选截断。区间内列出的流水不能直接求和当作累计已发或期末库存；库存还包括库存调整。

接口对历史数据提供过载保护：日期/编号条件下的候选订单最多 1,000 条，所选 BOM 最多 1,000 条，入库、出库各最多 1,000 条，类型隐藏前的关联节点合计最多 1,500 个。每类数据库查询最多读取上限加一条；一旦超量即返回 `400` 和缩短日期范围、按业务编号查询的提示，不返回被截断的图或不完整统计。候选订单上限作用于所有状态，因为 `counts` 需要同时计算它们；隐藏节点类型不能绕过上限。不限日期仍可用于小规模数据或精确查询，历史数据较多时请分日期区间或按订单、BOM、客户编号追溯。

已作废但未删除的入库、出库保留追溯，`facts.qty` 是登记数量；核算有效数量时排除 `facts.voided=true`。已删除订单、已删除单据物理消失不返回。入库只关联 BOM，不伪造订单对应关系；出库关联实际订单。人员、客户与 BOM 使用数据库实体 ID，即使同名也不合并。

`facts` 的关联 ID 指向图节点 ID，类型过滤后这些引用可能未出现在 `nodes`；核查完整链路时请求全部实体类型。完整字段定义见 [OpenAPI](../openapi.yaml) 的 `RelationsData`、`Relation*Facts`。
