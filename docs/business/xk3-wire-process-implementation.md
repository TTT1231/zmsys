# 旋转XK3 接线工艺二分 · 实施方案（待确认）

> 原型：`docs/prototype/xk3-wire-process-prototype.html`（评审稿）。
> 本文是结合现行代码（childCategories 机制 + 2026-09-21 上线的 BOM 备注判重）收敛的落地方案，
> **尚未实施**。焊线物料选项需按《XK3焊线物料清单》最终核对后开工。

## 方案：复用 childCategories「品类内变体」机制（与跌倒开关同构）

跌倒开关已有「先选微动开关类型（新微动/老微动）→ 再配物料」的完整链路（后端校验 +
目录合并 + 前端单选卡 + 切换清空确认）。XK3 二分完全复用，不引入新机制：

### 数据库（一个迁移）

1. **品类行**：新建 `xk3-wire`（焊线）与 `xk3-plug`（插线）两个品类行，挂各自专属目录；
   给 1002（旋转XK3）写 `child_categories = ["xk3-wire", "xk3-plug"]`。
2. **目录重排**（原型「共用分组 + 工艺专属分组」）：
    - 共用分组留在 1002：PC塑料外壳 / PC塑料底座 / PA66塑料杆子 / 静片（小静片、半圆静片，改多选）/ 动片（带圈动片）/ 弹簧（长、短，改多选）；
    - 插线专属搬到 `xk3-plug`：动片（平：不电镀/镀锡）/ 卡线片 / 4.0mm电镀钢球；
    - 焊线专属新建在 `xk3-wire`：3.0mm电镀钢球。
    - 存量 BOM 明细为建档冻结快照，目录搬移不影响已建档案。
3. **BOM 工艺标记**：`bom_table` 新增 `child_category` 列（建档时写入所选变体 key，仅用于
   展示与回溯）：存量 XK3 BOM（XK3001/XK3002）统一回填 `xk3-plug`；跌倒开关存量按明细中
   微动物料 id 段（31xx=新微动 / 32xx=老微动）回填。

### 判重指纹（保持三元组不变，实现取舍）

`spec_hash = SHA-256(品类 + 物料构成 + 备注)` **不加入工艺 key**：两种工艺的构成天然不同
（插线必含卡线片、焊线必含 3.0mm 钢球），指纹必然区分。原型第 3 点「工艺参与指纹」
针对的是"两工艺物料恰好全同」的边角（如都不选专属物料）——该场景由备注差异兜底；
若业务坚持工艺进指纹，需同步回填全部存量 child key 并升级四元组，改动面扩大一级。

### 后端

- `createBom`：现有 childCategory 校验与目录合并逻辑直接适用（loadCatalog 父+子合并）；
  建档写入 `child_category` 列；`toBom` 返回 `childCategory`。
- `GET /bom-categories`：品类新增可配置的子选标签文案（`child_label`，如跌倒=「微动开关类型」、
  X K3=「接线工艺」），替代前端硬编码的"微动开关类型"。

### 前端

- 选「旋转XK3」→ 出现「接线工艺：焊线/插线」单选卡（复用跌倒开关交互，文案取 child_label）；
  未选时物料区空态引导；切换工艺弹清空确认（现有 pendingChange 交互）。
- BOM 详情 / 出入库凭证摘要首位展示「接线工艺：焊线 / 插线」标签（由 child_category 渲染）。

## 存量影响

- XK3001 / XK3002 编码、明细、hash 全部不动；新建插线 BOM 与存量构成相同时判重命中直接复用。
- 跌倒开关行为不变（child 机制同一套）。
- 品类下拉会同时出现「焊线」「插线」两个子品类（与「新微动」「老微动」出现在下拉的现象一致）；
  直接从子品类建档会使用其独立前缀（建议设 XK3W / XK3P 防撞号），属边路路径，不推荐使用。
