# 表格体验讨论原型

直接打开 `index.html` 即可，无构建步骤、无外部资源、无业务接口。页面顶部可切换电脑与手机预览，侧边栏/底部导航可切换成品入库、成品出库和销售订单。

## 本轮范围

用于和业务使用者确认交互方向，尚未修改正式前端或部署线上。记录、库存与物料均为示例；原型中的角色不代表正式权限。

- BOM 默认宽度 350–370，优先获取可用剩余空间；编码不换行，规格一行摘要，可打开完整详情。
- 列宽独立调整，不挤压相邻列。鼠标悬停/键盘聚焦边界可高亮整列，拖动时明确提示列名；支持左右键与双击恢复。
- 单号与操作固定在两侧，小屏电脑允许表格内部横向滚动。纵向跟随页面，不再另设短小的内部滚动区。
- 显示设置采用“紧凑 / 标准 / 宽松”“推荐宽度 / 窄一些 / 宽一些”，支持隐藏列与恢复推荐，不显示像素输入框。
- 手机使用记录卡片、底部业务导航和全屏详情；无需横向拖动表格。手机的宽度选项隐藏，保留信息密度与显示内容。
- 搜索、品类/日期/人员/订单状态筛选、排序、翻页、CSV 示例导出可用。显示偏好按页面保存在浏览器本地。
- 新增、编辑、发货、打印仅显示提示；正式落地应接回原业务表单并保留权限、校验与审计。

## 待用户体验后确认

1. 桌面标准密度（编码、名称、规格两行）是否合适，是否需要长期显示第三行物料入口？
2. 独立列宽调整与显式高亮是否比相邻列挤压更顺手？
3. 手机记录卡片的首要字段、数量大小和发货入口是否符合实际工作顺序？
4. 订单字段较多时，是否接受保留关键列并横向滚动查看其余字段？

正式改造时需要统一 `DataTable`，调整三页列宽及移动端布局，并考虑升级已有用户的列宽偏好，避免旧的窄列配置覆盖新默认值。固定表头、极长值及更多真实业务状态需结合生产数据再评估。

## 原型验证

已用浏览器检查 1440 桌面布局，以及 320、390、768 宽度下三页的卡片布局与设置面板，页面无横向溢出。实际鼠标拖动 BOM 列增加 90，其余五列宽度保持不变；键盘左右键也可调整。搜索、空状态清除、翻页、数量排序、密度切换、列隐藏/恢复、人员与订单状态筛选、详情打开和内嵌手机预览均已检查。JavaScript 语法检查通过，浏览器无脚本错误。
