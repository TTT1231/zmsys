# 系统操作指南

本文说明可执行操作、前置条件和失败行为。写操作由服务端重新校验；页面按钮是否显示不能代替后端权限。HTTP 403 有两类：缺少权限码（可由超级管理员在「用户与权限」授权解决）与操作者身份限制（如归档回退仅原归档人本人、客户完整手机号仅负责人或超管可读——授权无法解除，需对应的人来操作），以错误信息为准；400 表示输入或操作条件无效，404 表示目标不存在，409 表示业务冲突、状态不符或版本已变化。遇到版本冲突先刷新数据，再由用户决定是否重试。

## 1. 客户档案

### 建档、编辑与手机号

- 谁能做：客户页面对超级管理员、管理员和销售开放；新建需 customers:create，编辑需 customers:edit，查看需 customers:view。默认授权见 roles 主题。
- 操作：创建客户档案；更新客户资料、负责人或付款条件。完整手机号须通过 GET /customers/{code}/phone 取用，普通客户列表始终只返回掩码。
- 前置条件：新建或变更后的负责人必须是启用中的销售或超级管理员。编辑使用当前 rowVersion；手机号明文只允许超级管理员读取任意客户，或销售读取自己负责的客户。
- 失败会怎样：负责人账号不存在为 404，负责人未启用或不属于允许角色为 400；版本过期为 409。非负责人销售读取完整手机号为 403；客户不存在为 404。

### 删除客户

- 谁能做：customers:delete 为受保护权限，默认仅超级管理员持有。
- 操作：通过 POST /customers/{code}/delete 物理删除误建档客户。
- 前置条件：客户没有任何销售订单引用；进行中和已归档订单都计入引用。已物理删除的订单不再计数。删除时提交接口返回的当前版本值。
- 失败会怎样：仍被任意销售订单引用时返回 409；版本变化返回 409；客户不存在返回 404。成功后客户立即从业务列表移除，op_log 保留删除前档案快照，不提供恢复入口。

### 批量移交负责人

- 谁能做：权限目录定义受保护的 customers:bulk-transfer；当前实现没有独立的客户批量移交 HTTP 端点。实际移交发生在用户管理接口，端点校验 permissions:manage（受保护，默认仅超级管理员）。
- 操作：通过 PUT /users/{account} 将销售改为其他角色，或通过 PATCH /users/{account}/status 停用销售时，服务端在同一事务内移交其名下全部客户。
- 前置条件：该销售仍负责客户时，必须提供接任账号和移交原因；接任者必须是启用中的其他销售。移交、历史记录和用户角色/状态变更原子提交。
- 失败会怎样：缺少接任人或原因、接任人不是启用中的其他销售时返回 400；用户不存在为 404；版本过期为 409。失败时移交和用户变更均不提交。customers:bulk-transfer 单独授权并不能替代端点实际要求的 permissions:manage。

## 2. 销售订单

### 创建订单

- 谁能做：orders:create。
- 操作：新建销售订单；请求以客户编码、BOM 编码和订单字段为输入，客户名称及 BOM 名称、规格由服务端查询并冻结快照。
- 前置条件：客户和 BOM 必须存在，数量大于 0；创建请求使用幂等键。同一用户、操作、幂等键和相同请求会重放原成功响应，同键不同请求内容返回 409。
- 失败会怎样：客户或 BOM 不存在为 404；无效数量等输入校验失败为 400；幂等键对应不同请求为 409。

### 编辑订单

- 谁能做：orders:edit。
- 操作：编辑客户、BOM、数量、交货日期或备注；每次更新按版本写入变更前后快照。
- 前置条件：订单必须为 ACTIVE。数量与交货日期的锁定看当前有效出库净额：净额大于 0 后二者锁定只能改备注，且数量不得低于有效净额。客户与 BOM 能否更换看现存单据：只要还存在关联出库单（包括已作废但未删除的），就不能更换；把关联出库单全部作废并删除后即可更换——即使订单曾经发货过（历史发货已全部冲销且单据清理后，有效净额回到 0）。
- 失败会怎样：订单已归档为 409；数量小于有效净额、净额大于 0 时改数量/交货日期、或仍有现存出库单时换客户/BOM 均为 409；目标客户/BOM 不存在为 404；版本过期为 409。

### 删除订单

- 谁能做：orders:delete 为受保护权限，默认仅超级管理员持有。
- 操作：通过订单删除接口物理删除误建订单。
- 前置条件：订单未归档、有效出库净额为 0，并且没有任何出库单。已作废但仍存在的出库单也算引用；需先作废再删除出库单。删除时提交接口返回的当前版本值。
- 失败会怎样：已归档、净发货非零或仍有出库单时返回 409；版本冲突返回 409；订单不存在返回 404。删除后业务行及订单变更日志被清理，系统日志保留删除前快照。

### 归档与回退归档

- 谁能做：归档需受保护权限 orders:archive；回退需受保护权限 orders:unarchive；默认均仅超级管理员持有。
- 操作：归档用于结案，回退用于修复误归档。没有取消生命周期，也没有取消接口。
- 前置条件：归档要求订单有效出库净额大于 0；原因可选。归档订单不再可编辑或新增出库，其欠量关闭。归档时即使仍有未作废出库单也会放行，但这些出库之后不能作废或删除。回退仅允许最初归档该单的同一操作者，其他超级管理员也不例外；没有时间限制。
- 失败会怎样：一件未发的订单归档返回 409，应删除误建单；已归档订单重复归档、未归档订单回退均为 409；非归档人回退为 403。回退后订单恢复 ACTIVE、编辑和发货能力，归档三要素清空，事件快照保留。

业务判断：一件未发且没有出库单的订单不再需要时，删除；已经形成有效发货的订单不再继续交付时，归档关闭剩余欠量。不要把“归档”称作“取消”。

## 3. 物料与 BOM

### 新建 BOM

- 谁能做：bom:create。
- 操作：按品类和目录中选择的物料构成创建成品档案。
- 前置条件：物料构成至少有一项；所选物料须归属有效目录且已启用，单选组最多选一项；有数量语义的分组按允许范围填数量。构成指纹包含品类、物料集合及数量、去空格后的备注。同一构成不同备注视为不同 BOM；构成和备注完全相同则重复。
- 失败会怎样：目录项无效或构成不符合规则为 400；命中已有指纹为 409，并返回已存在的 BOM 编码。成功后构成快照冻结，不能原地改 BOM 明细；构成变化需另建档案。

### 删除 BOM

- 谁能做：bom:delete 为受保护权限，默认仅超级管理员持有。
- 操作：删除未被使用的手误 BOM。
- 前置条件：没有任何销售订单引用（包括已归档订单），并且没有入库流水或库存调整流水。
- 失败会怎样：存在任一引用或流水为 409；BOM 不存在为 404。成功后删除档案及其 BOM 明细，op_log 保留删除前快照。

### BOM 结构维护

- 谁能做：查看结构需 bom-structure:view，维护需 bom-structure:manage；均为受保护权限，默认仅超级管理员持有，可由超级管理员解锁下放。
- 操作：在 BOM 结构维护中调整新建 BOM 可选的目录、物料或规则。
- 前置条件：提交当前 rowVersion。结构变化只影响此后新建的 BOM；已保存 BOM、销售订单和台账继续使用各自冻结快照。
- 失败会怎样：非法结构或违反目录冻结边界为 400；结构版本已变化为 409。已有 BOM 引用的物料不能被删除、改名或换组，被引用分组不能改名；应按维护规则隐藏旧项或新增目录项。旧 BOM 需要新构成时另建 BOM。

## 4. 成品入库

### 登记入库

- 谁能做：inbound:register，默认授予仓管和超级管理员。
- 操作：检验合格后登记成品入库，形成库存正向数量。
- 前置条件：BOM 必须存在；操作使用幂等键。登记时间由服务端记录，业务日期是单据日期。
- 失败会怎样：BOM 不存在为 404；输入校验错误为 400；同幂等键复用不同内容为 409。

### 当天修正或作废

- 谁能做：inbound:edit，默认授予仓管和超级管理员。
- 操作：当天修正 BOM、数量、业务日期、备注，或作废记录。修改或作废都必须填写原因并带最新版本。
- 前置条件：当天按 created_at 是否落在北京时间当前自然日判断，不按单据业务日期判断；修正始终限当天。作废后该笔不再计入库存。作废权限使用 inbound:edit；跨天作废还需受保护权限 inbound:void-any-day，默认仅超级管理员。
- 失败会怎样：跨天修正或无跨天作废权限返回 409；已作废记录重复修改为 409；作废或修正会使库存变负为 409；版本冲突为 409。

### 跨日库存调整

- 谁能做：inbound:adjust 为受保护权限，默认仅超级管理员持有。
- 操作：新增库存调整单记录跨日发现的数量差异；正数增加库存，负数减少库存。
- 前置条件：数量为非零有符号整数，必须填写原因；负向调整后库存不能小于零。可选关联一张仍存在的入库单，关联时 BOM 必须相同。调整单不可修改或删除；再次更正只能新增反向调整。
- 失败会怎样：负向调整导致库存小于零或关联 BOM 不同为 409；关联入库单不存在或已删除为 404；输入无效为 400。

### 删除作废入库单

- 谁能做：inbound:delete，默认授予仓管和超级管理员，属于可授权权限。
- 操作：物理删除已作废的入库单。
- 前置条件：单据状态必须为作废；若被库存调整单引用则永不删除，因为调整单不可变。
- 失败会怎样：仍有效或被调整单引用时返回 409；不存在为 404。成功后业务列表不再显示，系统日志保留删除前快照及作废原因。

## 5. 成品出库

### 登记发货

- 谁能做：outbound:ship，默认授予仓管和超级管理员。
- 操作：为销售订单登记出库，成功后即计入库存扣减和订单有效已发量。
- 前置条件：订单必须存在且为 ACTIVE；可发量 = min（当前库存，订单欠量）。同一 BOM 库存是共享桶，不按交期预留，先成功登记者先得。
- 失败会怎样：订单不存在为 404；归档订单或申请数量超过当前可发量为 409；输入无效为 400。并发时服务端在事务锁内重新计算，后提交请求可能因库存不足返回 409。

### 作废出库

- 谁能做：outbound:void，默认授予仓管和超级管理员。
- 操作：作废已登记单据；系统追加等额负向冲销流水，恢复库存与订单有效已发量。
- 前置条件：单据必须仍为 REGISTERED；提交作废原因和最新版本。所属订单已归档时，出库单成为审计依据，不可作废。
- 失败会怎样：重复作废或所属订单已归档为 409；版本冲突为 409；单据不存在为 404。

### 删除作废出库单

- 谁能做：outbound:delete，默认授予仓管和超级管理员，属于可授权权限。
- 操作：物理删除已作废单据；删除后从出库列表消失，op_log 保留删除前快照。
- 前置条件：状态必须为 VOIDED，且所属订单未归档。已归档订单下的出库单，即使在归档前已经作废也不得删除。
- 失败会怎样：单据未作废或所属订单已归档为 409；单据不存在为 404。

### 出库更正

出库没有原地编辑入口。发货登记错误且订单未归档时，由有权限者作废原出库，再按实际情况重新登记；原事件由等额冲销对冲。货物已经离库后的客户退货在系统内没有专门的退货流程——退货处理在线下按业务另行安排，系统不撤销原出库事实；如需修正账面，走作废重登或库存调整。

## 6. 系统与查看类

| 事项 | 谁能做及前置条件 | 失败与口径 |
| --- | --- | --- |
| 工作台 | menu:workbench；查询系统总览。 | 缺少菜单权限返回 403。 |
| 分析页关系图 | menu:analytics 与 menu:workbench 必须同时具备。细节、筛选、状态口径和过载限制见 analytics 主题。 | 缺任一权限返回 403；关系查询超限返回 400，应缩短日期或改按编号查询。 |
| 系统日志 | system-logs:view；默认仅超级管理员，超级管理员可在「用户与权限」授权。 | 缺权限返回 403；这是查操作人、时间、动作和原因的首选入口。 |
| 备份与恢复 | system-backup:run、system-restore:run 及对应菜单为受保护权限，默认仅超级管理员；可由超级管理员解锁下放。 | 缺权限返回 403；恢复属于高影响操作，必须按系统页面和维护流程执行。 |
| AI 工作台 | menu:ai-workbench 为受保护菜单权限，默认仅超级管理员，可解锁下放；控制模型、连接设置和用量。 | 缺权限返回 403。AI 对话和 agent 查询沿用登录态或业务查询权限，不要求 AI 工作台权限。 |

## 7. 查数据该去哪

| 用户的问题 | 优先端点或页面 | 使用提示 |
| --- | --- | --- |
| 今天入库多少 | GET /inbound 或 GET /workbench/overview | 入库列表含作废行；计算有效入库量时排除作废行，并按业务日期筛选。 |
| 某订单还欠多少 | GET /orders 或 GET /workbench/relations | 欠量 = 订单数量 − 有效出库净额；已归档订单虽可查，不再是活跃待交量。 |
| 谁改的、什么时候改的 | GET /system-logs?action=edit | 可再按 domain、keyword、时间范围筛选；按需要继续使用复合游标。 |
| 已删除的单据 | GET /ai/agent/deleted | 依赖 system-logs:view；结果是 delete_* 审计快照，不是业务主表记录。 |
| 作废的入库或出库单 | GET /ai/agent/voided/inbound 或 GET /ai/agent/voided/outbound | 分别需要 inbound:view 或 outbound:view；若单据后来已被物理删除，改查删除快照。 |
